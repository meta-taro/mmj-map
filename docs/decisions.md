# 決定と、その理由

**この製品がいまの形をしている理由**を、決めた順に並べたものです。

各項目は「決めたこと」「なぜ」「これを止めるべき条件」で書いてあります。
**止めるべき条件を書くのは、決定を永久にしないため**です。前提が変わったら覆してください。

番号（D-001 など）は他の文書から参照されています。**番号は再利用しません。**

---

## D-001 タイル生成パイプラインを自作しない（2026-09-14）

**決めたこと**: ベースタイルは Protomaps の日次プラネットビルドから切り出します。
OSM の生データからの変換パイプラインは書きません。

**なぜ**: そこを自作しても、この製品の差分は増えません。差分があるのはスタイルと UI 部品の側で、
変換パイプラインは既に解かれた問題です。

**採らなかった案**: tilemaker / planetiler で自前変換する → 数か月かかり、
出来上がるのは既にあるものと同じです。

**止めるべき条件**: Protomaps の日次ビルドが止まる、または利用条件が変わったとき。

## D-002 スタイルは生成物ではなく作品として扱う（2026-09-14）

**決めたこと**: スタイル JSON は手書きし、リポジトリで追跡し、レビュー対象にします。
ビルド生成物にしません。`.gitignore` で除外しません。

**なぜ**: 地図の美しさは、人が色を選んだ結果としてしか出ません。
生成物にした瞬間、この製品の唯一の差分が消えます。

**採らなかった案**: 配色をアルゴリズムで振る → それらしいものは出ますが、それらしいものは既にあります。

**止めるべき条件**: 手書きの差分が、汎用スタイルと見分けがつかない水準に留まるとき。

## D-003 地図サーバーを立てない（2026-09-14）

**決めたこと**: 静的配信と HTTP Range だけで完結させます。

**なぜ**: 運用が増えないことが、この製品の価値の一部です。
地図を出したいだけの人に、サーバーを 1 台持たせません。

**止めるべき条件**: 静的配信では成立しない要件（動的なスタイル生成など）が主要な用途になったとき。

## D-004 最初の区切りは新規実装ではなく切り出し（2026-09-14）

**決めたこと**: 先行実装から切り出して始めます。設計をゼロから引き直しません。

**なぜ**: 同じものを二度書かないためです。先行実装は本番で動いており、
踏むべき穴（Range の 206・字形の 404・分割アップロード）が既に判明していました。

**失うもの**: 初期構造に先行実装側の都合が残ります。UI を書き直すときに剥がします。

**止めるべき条件**: 切り出しが実質的に書き直しになると分かったとき。そのときは素直に書き直します。

## D-005 タイル生成の手順だけは切り出さず書き直す（2026-09-14）

**決めたこと**: 先行実装のローカル生成スクリプトは持ち込みません。

**なぜ**: 特定の PC のパス前提が残っており、**再現可能なビルドの条件を満たしません**。
「作った人がいなくなっても続くか」に直接効く場所です。

**採らなかった案**: 持ち込んでから直す → 動くものが手元にあると、直す動機が消えます。

## D-006 UI 部品は Web Components を軸にする（2026-09-14）

**決めたこと**: 目印・吹き出し・まとまりは Web Components。React / Vue は薄いラッパにします。

**なぜ**: フレームワークごとに本体を書くと、3 つの実装がずれていきます。

**採らなかった案**: React 版を本体にする → React を使わない利用者が最初から対象外になります。

**止めるべき条件**: ラッパが薄くならず、結局フレームワークごとの実装が要ると分かったとき。

## D-007 ライセンスはコードが MIT、データが ODbL（2026-09-14）

**決めたこと**: `LICENSE` は MIT 1 枚。データ側の条件は `LICENSES.md` に分けて書きます。

**なぜ**: スタイル JSON は**データではなく表現**なので ODbL の対象外です。
一方でベースタイルは OSM 由来で ODbL。混ぜて書くと、どちらも守られません。

**必ず守ること**: 画面から `© OpenStreetMap contributors` を消さないでください。

## D-008 費用削減を目的に掲げない（2026-09-14）

**決めたこと**: 「地図の費用が下がる」を、この製品の目的にも成果にも書きません。

**なぜ**: 座標の取得元が「その提供者の地図の上に表示すること」を条件にしている場合、
**ベース地図だけを差し替える自由はありません**。効く条件が限られるものを効果として約束すると、
採用した人が後で困ります。

## D-009 タイルビルドは Node で書く（シェルスクリプトにしない）（2026-09-15）

**決めたこと**: `tools/tiles` を Node + TypeScript で書き、外部コマンドの呼び出しだけを子プロセスに出します。

**なぜ**: 実行環境は Node です。ビルド経路だけ POSIX シェルにすると、
**Windows の開発機では手元で 1 行も走りません**。テストの道具もリポジトリ内で 2 系統になります。

**止めるべき条件**: タイル生成が Node から離れ、外部ツールの順次実行では足りなくなったとき。

## D-010 上流ビルドは固定し、自動では乗り換えない（2026-09-15）

**決めたこと**: `tools/tiles/manifest.json` に上流ビルドを 1 個固定します（キー / サイズ / チェックサム / 版）。
`pnpm tiles:resolve` が上流の索引と突き合わせ、**差があれば落ちます**。乗り換えは人が `--update` を打ちます。

**なぜ**: 再現可能なビルドとは「同じ入力から同じ出力」が言えることです。
毎回「最新」を取りに行く形は、**同じコマンドが日によって違う地図を作る**ので再現可能ではありません。
上流のスキーマ版が変わるとスタイルが壊れるため、**版が動いたことに気づける場所**も要ります。

**止めるべき条件**: 上流が日付ではない固定 URL の安定版を出し、
そちらのほうが中身の同一性を強く保証するようになったとき。

## D-011 点のまとめは地図ライブラリに任せ、件数は色ではなく大きさで表す（2026-09-17）

**決めたこと**: `<mmj-cluster>` は GeoJSON source のまとめ機能を設定し、
排他の条件を持つ 3 枚のレイヤを足すだけにします。**まとめる計算を自分で書きません。**
まとまりの大きさは件数で 3 段階に変え、**色は件数によって変えません**。

**なぜ**: MapLibre の GeoJSON source はまとめる仕組みを内蔵しており、ズームごとの再計算まで持っています。
同じものを外に書くと、**タイルではなく点の集計で地図が重くなる**場所を自分で作ることになります。
また、件数を色の段階で表すのは配色を決める行為です。大きさなら、後から配色を決めても壊れません。

**採らなかった案**: 件数を色の段階で表す → 凡例のない色の段階は、読む人ごとに違う意味に読まれます。

**止めるべき条件**: 点が数万件を超えて source 側のまとめが間に合わなくなったとき。
そのときは点を**タイルにする**話であって、まとめる計算を自作する話にはなりません。

## D-012 ベクタタイルは自前で読む。数えるためにライブラリを足さない（2026-09-17）

**決めたこと**: `tools/tile-inspect` がベクタタイルを自前でデコードします。デコード用の依存を足しません。

**なぜ**: 用途は「何が何件あるか」を数えることだけです。形式は固まっていて、
属性まで読むなら 150 行で済みます。依存を足すと、その版と脆弱性を見続けることになります。

**止めるべき条件**: 幾何を読む用途が常態になったとき。座標の検証や面積の集計を始めるなら、
自前で持つ理由はなくなります。

## D-013 広域の切り出しは四角 1 個ではなく、四角の集合で行う（2026-09-17）

**決めたこと**: 日本の切り出しを倍率で 2 段に分け、低倍率は全域の四角、高倍率は**8 つの四角**で切って結合します。
海岸線はなぞりません。**落としていないことは機械のテストが止めます**（四隅を含む 35 点）。

**なぜ**: 四隅の離島を 1 つの四角で囲うと、太平洋をまるごと抱えます。
実測で **3.6 GB → 2.8 GB（-22%）**、タイル件数は **-53%**。遠方の島は 1 つも落ちていません。

**採らなかった案**:

- 海岸線の多角形を使う → 書いた人が読めなくなります。四角 8 個なら、どこを含めたか目で確かめられます
- 遠方の島を落として面積を減らす → 「日本の地図」ではなくなります

**やっていないこと**: **最大倍率は触っていません**。容量の本丸はそこですが、
どこまで寄れる地図にするかは品質の判断です。

**止めるべき条件**: 四角を足しすぎて人が読めなくなったとき。

## D-014 固定は 1 本のまま。ただし確認済みの旧版を 3 本まで持ち、引数で戻れるようにする（2026-09-17）

**決めたこと**: 確認済みの旧版を最大 3 本持ち、`--build=previous` などで切り出せるようにします。
**固定した版以外で切ったら、出力名に版が入ります**。設定に無い版は使えません
（引数で任意の URL を取りに行かせません）。

**なぜ**: D-010 で固定を 1 本にしたのは「同じコマンドが日によって違う地図を作らない」ためで、そこは変えません。
ただし固定 1 本では**戻り先がありません**。道も地物も上流で日々変わるので、
新しい版で何かが壊れたときに手で設定を書き換えるしか手が無い状態でした。

**出力名に版を入れる理由**: 同じ名前へ上書きすると、
**時間をかけて作った新しい方を古い版で潰す事故**が起きます。

**止めるべき条件**: 3 本より前へ戻る必要が繰り返し出るとき。
そのときは戻り方ではなく、上流に乗り換える判断の頻度の問題です。

## D-015 lint は oxlint を使う（2026-09-17）

**決めたこと**: 手元と CI の lint を oxlint で回します。採るカテゴリは correctness / suspicious / perf の 3 つです。

**なぜ**:

1. この時点の typescript-eslint は、このリポジトリの TypeScript の版を対象外にしていました
2. oxlint は install script を持たず、実行時依存もありません
3. 指摘の実測（59 ファイル）で、pedantic 95 件・style 1558 件は**手書きのコードの書き方そのものを
   書き換える指摘**が大半でした。**赤が常態になったゲートは読まれなくなる**ので入れていません

**重要度を error にしてあります**。既定は warning で、**違反を報告しながら終了コード 0 を返す**ためです。
この 1 点はテストで縛ってあります。

**止めるべき条件**: eslint 側の資産が必要になり、かつ版の問題が解消したとき。
そのときは**この決定を書き換えてから**乗り換えてください。

## D-016 スタイルの 1 枚目はダークにする（2026-09-17）

**決めたこと**: Modern Dark を 1 枚目にします。

**なぜ**:

1. テーマは結局、導入時に利用者が決めます。1 枚目に時間をかけて悩む価値が薄い
2. 最初は「既存の他サービスとの違いが分かる」ことが望ましい。主要な地図サービスは明るい地図が既定なので、
   暗い地図はそれだけで違いが立ちます

**この決定が持つ含み**: 理由 1 は「**テーマは差し替えられる前提で作る**」ということでもあります。
1 枚目を作り込むより、2 枚目を足せる形を保つほうが効きます。

**止めるべき条件**: 導入先が「明るい地図でないと使えない」と言ったとき。
そのときは 1 枚目を入れ替えるのではなく、**2 枚目を足して選べるようにする**のが筋です。

## D-018 正式名称を「MMJ」にする。対象地域を日本の外へ広げる（2026-09-21）

**決めたこと**: 正式名称は MMJ。対象地域は日本に限りません。

**なぜ**: 実装を調べた結果、**日本に縛られている機能コードは 1 つもありませんでした**。
日本が現れるのは 3 か所だけで、どれもデータか既定値です（地域の多角形・文字のフォント指定・
スタイルのラベル参照 1 行）。上流は地球全体のビルドで、中心と半径の指定は最初から世界で動きます。

**道具は世界、スタイルは地域ごと**: 広げても差別化は捨てません。
差別化は「地名の密度・文字種の混在・事業者ごとの路線色」という**その地域固有の条件へ向けた作り込み**です。
地域ごとに作るのはスタイルのほうです。

**止めるべき条件**: 地域を増やした結果、どの地域のスタイルも中途半端になったとき。

## D-019 配色は 6 枚持つ。構造は 1 つに固定し、違うのは色だけにする（2026-09-21）

**決めたこと**: `styles/` に 6 枚（dark / light / ink / sand / neon / candy）。
**レイヤ構成・条件・倍率の範囲・配置・線の太さは 6 枚とも同一**にし、違うのは色だけにします。
一致はテストが見ます。

**なぜ**: 配色違いを増やすと構造が少しずつずれ、
**「dark では出るのに light では出ない地物」**が生まれます。どちらが正しいか誰にも分からなくなります。
D-002 は「色を人が選ぶ」という決定であって、構造まで枝分かれさせる決定ではありません。

**色相を使う 2 枚について**: neon / candy は道の序列を明るさではなく色相で分けています。
**色相に意味を持たせられる唯一の場所が道路の階層**で、ここ以外で使うと色が何を指しているのか読めなくなります。

**止めるべき条件**: 6 枚のうち人が実際に使うのが 1〜2 枚しかないと分かったとき。枚数を保つために手を入れません。

## D-020 導入者の色は「渡してもらう」。こちらで作らない（2026-09-21）

**決めたこと**: `<mmj-map>` に 2 つの入口を足します。

- `accent="#0A5FFF"` … テーマカラー 1 色。高速道路と駅の縁に当たり、目印や自前の点の既定色にもなります
- `palette-url="./brand.json"` … 24 の役割を指定します。書いた役割だけが当たります

吹き出しの色は、読み込んだスタイルから借ります。

**なぜ**: 導入先にはたいていテーマカラーがあります。
**180 行のスタイル JSON を書かせるのは「調整可能」であって「便利」ではありません。**
受け取った色を役割へ当てるだけなら、こちらが色を作らずに済みます。

**地図全体は塗りません**: `accent` が当たるのは 2 か所だけです。全部を 1 色で塗ると、
陸・水・建物・道の区別が付かなくなり、地図として読めなくなります。

**止めるべき条件**: `accent` の当たり先が「テーマカラーが効いている」と感じられないと分かったとき。

## D-021 配色の生成は「導入者の道具」として切り出す（2026-09-21）

**決めたこと**: `tools/palette` を作ります。指し値（陸・水・文字・テーマカラー）から 24 役割の配色、
またはそのまま配れるスタイル JSON を作ります。

**D-002 との関係**: D-002 が却下したのは「配色をアルゴリズムで振る」ことです。
**`styles/` の 6 枚は手書きのまま**で、そこは変えていません。生成するのは導入者が持つ配色で、
出力には生成物であることを示す印を入れ、手書きの作品と見分けられるようにしてあります。

**部品の中ではなく別の道具にした理由**:

1. 部品が重くならない
2. **出した配色を人が手で直せる**（実行時生成だと直す場所がありません）
3. 配る側と作る側の境界が、ファイルの場所として見えます

**止めるべき条件**: 生成した土台のほうが、手書きの 6 枚より使われるようになったとき。
そのときは「作品として作る」という前提自体が間違っていたことになります。

## D-022 経路は描くが、計算しない。吹き出しは DOM で組む（2026-09-21）

**決めたこと**: `<mmj-route>` は**渡された GeoJSON を描くだけ**です。線、押すと開く案内、写真つきの案内。

**計算しない理由**: 計算には道路グラフと経路探索の仕組みが要り、**D-003（地図サーバーを立てない）の外側**です。
作るのは外（経路 API でも AI でも）。**描く側に徹するのが「データを持たない。表現を持つ」の形そのもの**です。

**文字列を HTML として実行しません**: 登録された文字列をそのまま HTML にすると、
1 行で**その地図を置いたページ全体が乗っ取られます**。
中身は要素生成と文字列代入だけで組み、文字が HTML として解釈される経路がそもそも存在しません。
`javascript:` と `data:` の画像は黙って落とします。

**止めるべき条件**: 経路を計算してほしいという要望が繰り返し出たとき。
そのときに考えるのは「MMJ が計算する」ではなく「**どの経路 API と繋ぐ例を配るか**」です。

## D-023 カバレッジを測り、80% を割ったら CI で止める（2026-09-21）

**決めたこと**: `pnpm coverage` でワークスペース全体を 1 回で測り、閾値 80% を CI に入れます。

**最初の実測（除外なし）**: statements 69.4% / branches 70.0% / functions 73.8% / lines 71.1%。
**80% に届いていませんでした。**

**やったこと**: 配信サーバーの本体が 34% で、`Range` を解釈するテストはあるのに
**206 を組み立てる本体が 1 行も通っていませんでした**。本物のサーバーを起こして HTTP を投げるテストを足し、
90% にしました。**Range に 206 で応えられなければ地図は 1 枚も出ません。**

**測らないと決めたもの**（理由つきで明記してあります）: 入口のファイル、
ブラウザで撮って確かめる要素、上流から実測値を取り直す道具。
除外には「**数字を上げるために除外を足さないこと**」と書いてあります。

**閾値が本当に落ちることを確かめました**（一時的に 99% にして、落ちるのを見てから戻しました）。

**止めるべき条件**: 閾値を下げたくなったとき。そのときに直すのは閾値ではなく、テストか除外の理由のほうです。

## D-024 ラベルの言語は属性で切り替える。地域ごとにスタイルを増やさない（2026-09-21）

**決めたこと**: `<mmj-map lang="zh-Hant">` で、読み込んだあとにラベルの参照先を差し替えます。
スタイルは 6 枚のままです。文字のフォントも属性で差し替えられます。

**なぜ**: 地域ごとにスタイルを複製すると、配色 6 枚 × 地域で 24 枚 48 枚と増え、
**色を直すたびに全地域へ配る**ことになります。

**その言語の名前が無い地物は、元の名前のまま出ます。消しません。**

**実測**（大阪のタイル）: `name:en` 508 / `name:zh-Hant` 20 / `name:zh-Hans` 20 / `name:ko` 9 / `name:vi` 2。
**`name:zh` は存在しません**（`zh-Hans` / `zh-Hant` に分かれています）。

**件数が少ない ＝ 効かない、ではありません**: 台北のタイルには `name:zh-Hant` が 215 件入っており、
台北市 → 臺北市 → Taipei と切り替わります。大阪で変化が小さかったのは、そのタイルに無かっただけです。

**日本の外では `lang` を必ず付けてください**: 配るスタイルは日本語名を優先するため、
付け忘れると**日本語名を持つ地物だけ日本語**で出ます。

**止めるべき条件**: 1 つの地図に複数言語を混ぜたくなったとき。
それは差し替えでは足りず、スタイル側の設計の話になります。

## D-025 リポジトリ名を `mmj-map` にする（2026-09-24）

**決めたこと**: `modern-map-japan` → `mmj-map`。公開 URL は <https://meta-taro.github.io/mmj-map/>。

**なぜ**: 名前が 3 つに割れていました（製品 MMJ / パッケージ `@mmj-map` / リポジトリ `modern-map-japan`）。
加えて `japan` が実態と合っていません（D-018 / D-024）。

**リダイレクトは半分だけです**（実測）:

## D-027 切り出しを `npx` で配る。外では固定ではなく最新を取る（2026-09-25）

**決めたこと**: `npx @mmj-map/tiles extract <名前> --bbox=...` で、clone せずに切り出せるようにします。

| | 使う上流 | 出力先 | 設定の書き換え |
|---|---|---|---|
| リポジトリの中 | **固定**（D-010 のまま） | `dist/tiles` | できます |
| 外（`npx`） | **実行時に索引から最新** | 叩いた場所の `./tiles` | **しません。しようとしたら断ります** |

**なぜ外では固定を使わないか**: 固定した版は 1 週間ほどで上流から消えます（実測 9 日）。
**配った道具が固定だけを見ていたら、配った翌週に 404 で止まります。**
代わりに**出力名へ版を入れます**。D-010 の目的は「どの版で作ったか後から言えること」なので、
名前に入れば満たせます。

**出したあとに「乗るかどうか」まで言います**: バイト数だけでは判断できません。
上限を知らない人は、数字を見ても分かりません。

**止めるべき条件**: 上流が「最新」を返す索引をやめたとき。
または、外向けに最新を取ることが再現性の問題を実際に起こしたとき。

## D-028 地図の部品（帰属表示・縮尺・操作ボタン）も、読み込んだ配色に合わせる（2026-09-25）

**決めたこと**: `<mmj-map>` が、読み込んだスタイルから借りた 3 色を帰属表示・縮尺・操作ボタンへ当てます。

**なぜ**: 地図ライブラリの既定は白地で、暗い地図の上では**紙が 3 枚浮いて見えます**。
公開デモ 10 枚すべてで出ていました。

**帰属表示は消しません・薄くしません**: `© OpenStreetMap contributors` は
**ODbL の条件であって体裁ではありません**。やるのは「読める形で地図に馴染ませる」ところまでで、
非表示や透明化は書きません。**テストで縛ってあります。**

**3 つ直します。2 つだと前より目立ちます**: 最初は帰属表示と縮尺だけ直しましたが、

## D-030 開いているカードは `?shop=` に置く。`#` には置かない（2026-09-28）

**決めたこと**: `<mmj-poi card-id="...">` を渡したとき、開いている点を **query（`?shop=<id>`）**へ書きます。
`location.hash` には書きません。

**なぜ**: **`#` は地図が持ち主だからです。**`<mmj-map hash>` を付けると地図ライブラリが
`#15/34.70/135.49` を書きますが、**その実装は自分の形以外を捨てます**。
`#shop=` に置くと、**地図を少し動かした瞬間に消えます。**

**繋ぐ前に気づけました**: 繋いでいたら、テストは通ったまま出ていました。
消えるのは「カードを開いて、地図を動かして、それから URL を送った」ときだけで、画面には何も出ません。
**共有された側が「地図しか出ない」と言って、初めて分かる形**でした。

**代わりに払ったもの**: `?shop=` は Service Worker の照合鍵に入るので、
**同じ頁なのに控えが見つからなくなります**。文書の控え探しは検索文字列を無視するようにしました。
**共有された URL をオフラインで開くのは、いちばん効いてほしい場面**です。

**採らなかった案**:

| 案 | 採らなかった理由 |
|---|---|
| 名前付きの `#` に変える | **すでに配った URL が壊れます** |
| 地図が書いた後に書き足す | 地図側は遅らせて書くので、**先後が運任せ**になります |
| URL に残さない | 「この店いいよ」と送れません |

## D-031 本文の HTML は、置く側が項目を名指ししたときだけ開く（2026-10-05）

**決めたこと**: `<mmj-poi card-rich="description">` のように**項目を名指ししたときだけ**、
その項目を HTML として読みます。既定は文字のままです（D-022 は変えません）。

許すのは `a` `b` `br` `em` `i` `li` `ol` `p` `strong` `ul` の 10 個、属性は **`a` の `href` だけ**。
`target` と `rel` はこちらが付けます。

**なぜ opt-in なのか**: 「HTML が危ないから」ではありません。
**誰がその文字列を書くかを、部品が知らないから**です。

- 置く側が自分でデータを書くなら、HTML を許しても**自分のページに自分で書くのと同じ**で安全
- ただし**店舗が CMS で紹介文を書く**使い方や、`card-live` が実行時に取りに行く JSON では、
  書く人は置く側ではありません。1 件が `<img src=x onerror=…>` を書くだけで、
  **その地図を置いた全ページ**が乗っ取られます

**部品はどちらか判定できません。**だから既定を安全側に置いたまま、開けるようにしました。

**実装の形**: 解析には `DOMParser` を使いますが、**読んだ木をそのまま挿しません**。
読み取って `createElement` で作り直すので、入るのは許可表にあるものだけです。
**禁止を数えません**（`onerror` を 1 つずつ落とす形は、新しい属性が増えるたびに穴が開きます）。

**作っている途中で 1 つ踏みました**: 許可表に無いタグは「タグだけ落として中の文字を残す」
としていたため、**`<script>` の中身が文字としてカードに出ました**（実行はされていません）。
画面に出す文章を持たないタグは**中身ごと捨てる**ように直しました。

**採らなかった案**:

- **生の HTML をそのまま通す**（`setHTML` / `innerHTML`）→ 置く側が自分で書く場合は問題ありませんが、
  **部品はそれを判定できません**。既定にはしません
- **用途ごとに属性を増やす**（予約・求人・採用…）→ 際限がなく、**一例を足し続ける**ことになります。
  ラベル付きのリンクは `card-links` が既に任意の数を受けるので、そちらで足ります

**止めるべき条件**: 許可表を広げたくなったとき。**広げるのは「文章に要るか」だけ**で判断し、
`img` のように**属性を落としても置き場になるもの**は入れません。

## D-032 MapLibre を 6 系へ上げる。読み込みは ESM 1 本に寄せる（2026-10-06）

**決めたこと**: MapLibre GL JS を 5.24.0 から **6.12.0** へ上げます。
利用者の HTML は `<script src=…maplibre-gl.js>` ではなく、
`<script type="module">` で `maplibre-gl.mjs` を輸入して `window.maplibregl` へ置く形になります。

**部品が見ているものは変えていません。**`mmj-map` ほかは今までどおり `window.maplibregl` を読みます。
5 系を読んでいるページは、そのまま動きます。

**なぜ書き方まで変わるのか**: 6 系は **ESM だけを配っている**からです。

| | 5.24.0 | 6.12.0 |
| --- | --- | --- |
| `dist/maplibre-gl.js`（UMD） | ある（1032 KB） | **無い**（HTTP 404） |
| `exports` | main / module の両方 | `{"import": "./dist/maplibre-gl.mjs"}` だけ |
| 要るファイル | 1 本 ＋ CSS | `maplibre-gl.mjs` ＋ `-shared.mjs` ＋ `-worker.mjs` ＋ CSS |
| WebGL | v1 可 | **WebGL2 必須** |

版だけを 6 に書き換えると **404 になり、地図が 1 枚も出ません**。
だから導入手順を 5 言語とも書き換えました。

**同梱は 3 本**。入口が隣の `-shared.mjs` を輸入し、worker は `import.meta.url` から
`-worker.mjs` を組み立てます。1 本でも欠けると、ビルドもテストも通ったまま実行時にだけ壊れます。

**なぜいま上げたのか**: 2026-09-16 に一度見送っています。そのとき残した条件が
「**可視な環境で描画を確認してから**」でした。見送りの理由は「UMD が読める」の一点で、
6 系を落とした根拠は無く、確かめようとした環境のタブが不可視で rAF が発火せず、
**5 系でも 6 系でも同じ「無反応」になって区別が付かなかった**だけです。

条件を満たしたので上げました。確かめたこと（6.12.0・2026-10-06）:

- 可視な環境で描画した。タイル・ラベル・縮尺・帰属が出る
- **配色 6 枚すべてが描ける**。style-spec v25 は旧式の式を例外にするようになりましたが、
  手書きのスタイルは 1 つも拒まれなかった
- **`hash` の書式は変わっていない**（`#16.23/34.699243/135.502607/0/60`）。
  6 系は hash を `URLSearchParams` で扱うようになったので、`=` を含む形に変わっていれば
  `hashOverridesPitch` が静かに効かなくなるところでした。pitch を hash で渡す経路も実測で確認
- 全 16 頁で console 0 件・失敗した通信 0 件。`pnpm smoke` は 32 枚で指摘なし

**途中で 2 つ踏みました**（どちらも「緑のまま壊れる」形）:

1. **手元の開発サーバーが `.mjs` を `application/octet-stream` で返していた。**
   頁は 200、失敗した通信も 0 件、それでもブラウザは module の実行を拒み、
   地図だけが出ません。拡張子を 1 つ足し忘れただけでこうなるので、
   **配信後に content-type を測る検査**を deploy に入れました
2. **撮影の道具が 25 秒待ち切るようになった。**5 系の worker は `blob:` で、
   「scheme が http(s) か」で除いていました。6 系の worker は普通の URL になり、
   同じ規則をすり抜けます。worker は別の target で走るので応答が page 側へ来ず、
   永久に終わりません。**URL ではなく `initiator` で仕分ける**形に直しました

**採らなかった案**:

- **部品に「MapLibre の URL」属性を足して、部品自身に輸入させる** →
  `window.maplibregl` という入口が 2 つになります。5 系を読んでいる人の HTML を
  動かし続けたいので、入口は 1 つのままにしました。橋渡しは 3 行です
- **5 系に留まる** → 根拠が「UMD が読める」だけで、WebGL2 必須・上流の修正・
  style-spec の更新から離れていきます。**見送りの条件は満たした**ので上げました

**止めるべき条件**: 配信先が `.mjs` を JavaScript として返せないとき。
そのときは地図が出ないので、deploy の検査が赤で止めます。
