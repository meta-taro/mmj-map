# 定期点検（PDCA）

言われてから直すのをやめるための手順。**月に 1 度**、または大きな機能を入れた直後に通す。

この文書は減らさない。踏んだ穴は下の表へ足す。

---

## 0. 測る（推測で案を並べない）

数字を先に出す。出さないと、次回との比較ができない。

```bash
pnpm gate                 # lint / 型 / テスト / 参照 / スタイル / エージェント文書
pnpm smoke                # 全頁を 2 幅で開いて、壊れていないか
pnpm tiles:check-age -- "https://meta-taro.github.io/mmj-map/tiles/demo.pmtiles"
```

| 見るもの | 取り方 |
| --- | --- |
| 依存の版の遅れ | `npm view maplibre-gl version` と `package.json` を比べる |
| リンク切れ | `llms.txt` の URL を全部叩く（下の例） |
| 説明文の長さ | 検索結果で切られる目安は 120 字 |
| 本番の見た目 | `pnpm shot` で 1440x900 と 390x844 の両方 |

```bash
grep -oE 'https://meta-taro\.github\.io/mmj-map/[^)]*' apps/demo/llms.txt | sort -u |
  while read -r u; do printf "%s %s\n" "$(curl -s -o /dev/null -w '%{http_code}' "$u")" "$u"; done
```

## 1. 外を見る（競合と landscape）

自分の中だけを見ていると、世の中が動いたことに気づけない。

- 同じ問題を解いている実装。**何を持っていて、何を持っていないか**
- 依存の上流（MapLibre / PMTiles / Protomaps）の版と、壊れる変更
- 検索と AI の扱いの変化。**流行りではなく、根拠のあるもの**を見る

調べた結果は、採否と理由を `decisions.md` へ。採らなかったものも書く。

## 2. 並べて、上から 3 つだけやる

全部やろうとすると、どれも中途半端になる。**効き目 ÷ 手間**で並べ、上から 3 つ。

残りは次回へ送る。送ったことを書いておく（忘れたのか、送ったのかが分かるように）。

## 3. 実物を見る

画面を変えたら、人に見せる前に自分で見る。

- 1440x900 と 390x844 の両方
- 触れそうに見えるものを全部触る（タブの中身は `pnpm shot --click=` で開ける）
- **本番の形で見る**。手元だけで通る条件で確かめない

## 4. 検査に落とす

人が気をつける方式は必ず漏れる。直したら、同じことが起きないよう機械で止める。

いま動いている検査:

| 検査 | 何を見るか |
| --- | --- |
| `pnpm asset:check` | 参照されているのに無いファイル／データに混ざった文章の記法 |
| `pnpm agent-doc:check` | 属性と文書のずれ／索引のリンク切れ／生成物の古び |
| `pnpm smoke` | 全頁を 2 幅で開いて、押す目標の大きさや重なり |
| `oss-placement-check` | 作業の記録が git に入っていないか |
| `oss-privacy-check` | 個人名とメールアドレス |
| `tiles:check-age` | 配っているタイルが何日前のものか |

**足した検査は、1 度わざと壊して赤くなることを見る**。落ちない検査は、無い検査と同じ。

## 踏んだ穴（足していく）

| 穴 | 手順のどこで防ぐか |
| --- | --- |
| エージェント向けの索引で、10 本中 4 本が 404 だった（公開サイトに無い頁へ根を付けていた） | 0（リンクを全部叩く）→ 4（検査に落とした） |
| 依存がメジャー 1 つ分遅れていた（MapLibre 5.24 → 6.12）のに気づいていなかった | 1（上流の版を見る） |
| 説明文が全 16 頁で、目安 120 字の半分以下だった | 0（長さを測る） |
| 文章の記法がデータへ漏れ、画面にアスタリスクが出た | 4（検査に落とした） |
| パイプが終了コードを飲み、CI が緑のまま何もしていなかった | 4（わざと壊して赤を見る） |
| タブの中身を画面で確かめられず、確認を人へ回した | 3（`--click=` で開く） |
| 配信側が `.mjs` を octet-stream で返し、頁は 200・通信の失敗 0 件のまま地図だけが出なかった | 3（実物を見る）→ 4（配信後に content-type を測る検査を deploy へ） |
| 撮影の道具が、6 系の worker を「終わらない通信」と数えて毎回 25 秒待ち切っていた | 0（測る道具自身を疑う。URL ではなく `initiator` で仕分ける） |
| 確かめる側が古い部品を掴んでいた（`apps/demo/elements/` の複製が 5 本ずれたまま撮っていた） | 3（**確かめる側も疑う**。撮る前に複製を揃える） |
| 太字が `**` のまま画面に出ていた（公開中の文書 20 本・223 箇所。npm の頁にも出ていた） | 4（検査に落とした。`asset:check` が git 管理下の `.md` を見る） |
| npm に出ている版が 2 週間前のままで、文書が説明する部品の多くが入っていなかった | 0（公開物と手元を突き合わせる） |
| npm の頁で画像が死んでいた（`../screenshots/` がパッケージの外を指していた） | 0（出した頁を実際に開く） |
| robots.txt を置いたが、下の階層なので読まれない（GitHub Pages の project site は `/<repo>/` 以下。robots.txt はホストの根しか読まれない） | 0（置いたものを実際に叩く）→ ファイル自身へ「効いていない」と書いた |
