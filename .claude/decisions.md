# 決定と、その理由

新しい決定は**下に足す**。書き換えない。止めた決定は「止めた」と書いて残す。

各項目は 4 つで書く — **決めたこと / 根拠 / 採らなかった案とその理由 / これを止めるべき条件**。

---

## D-001 タイル生成パイプラインを自作しない（2026-09-14）

- **決めたこと**: ベースタイルは Protomaps の日次プラネットビルドから切り出す。
  OSM の生データからの変換パイプラインは書かない。
- **根拠**: そこを自作しても、**この企画の差分は 1 ミリも増えません**。
  差分があるのはスタイルと UI 部品の側で、パイプラインは既に解かれた問題です。
- **採らなかった案**: tilemaker / planetiler で自前変換する。
  → 数か月かかり、出来上がるのは既にあるものと同じです。
- **止めるべき条件**: Protomaps の日次ビルドが止まる、または利用条件が変わったとき。

## D-002 スタイルは生成物ではなく作品として扱う（2026-09-14）

- **決めたこと**: スタイル JSON は手書きし、リポジトリで追跡し、レビュー対象にする。
  ビルド生成物にしない。`.gitignore` で除外しない。
- **根拠**: **地図の美しさは、人が色を選んだ結果としてしか出ません。**
  生成物にした瞬間、この企画の唯一の差分が消えます。
- **採らなかった案**: 配色をアルゴリズムで振る。
  → それらしいものは出ますが、**それらしいものは既にあります**。
- **止めるべき条件**: 手書きの差分が汎用スタイルと見分けがつかない水準に留まるとき
  （そのときは企画ごと見直す）。

## D-003 地図サーバーを立てない（2026-09-14）

- **決めたこと**: 静的配信 ＋ HTTP Range で完結させる。
- **根拠**: **運用が増えないことが、この製品の価値の一部です。**
  地図を出したいだけの人に、サーバーを 1 台持たせない。
- **採らなかった案**: タイルサーバーを同梱する。
  → 「サーバーを立てなくてよい」という利点そのものを捨てることになります。
- **止めるべき条件**: 静的配信では成立しない要件（動的スタイル生成など）が
  主要な用途になったとき。

## D-004 最初のスプリントは新規実装ではなく切り出し（2026-09-14）

- **決めたこと**: 原案の Phase 1 / Phase 4 は書き起こさず、先行実装から切り出す。
- **根拠**: **同じものを二度書かないため。**先行実装は本番で稼働しており、
  踏むべき穴（Range 206・グリフの 404・分割アップロード）が既に判明しています。
- **採らなかった案**: 設計をゼロから引き直す。
  → 自由は増えますが、**既に分かっている失敗をもう一度踏みます**。
- **失うもの**: 初期構造に、先行実装側の都合（配信先の選び方・フレームワーク）が残ります。
  S2 で UI を書き直すときに剥がします。
- **止めるべき条件**: 切り出しが「固有の語を外す」では済まず、
  実質的に書き直しになると分かったとき（そのときは素直に書き直す）。

## D-005 タイル生成ワークフローだけは切り出さず書き直す（2026-09-14）

- **決めたこと**: 先行実装のローカル生成スクリプトは持ち込まない。
- **根拠**: **特定の PC のパス前提が残っており、再現可能ビルドの条件を満たしません。**
  「作った人がいなくなっても続くか」（PRD §0）に直接効く場所です。
- **採らなかった案**: 持ち込んでから直す。→ 動くものが手元にあると、直す動機が消えます。

## D-006 UI 部品は Web Components を軸にする（2026-09-14）

- **決めたこと**: Marker / Popup / Cluster は Web Components。React / Vue は薄いラッパ。
- **根拠**: フレームワークごとに本体を書くと、**3 つの実装がずれていきます**。
- **採らなかった案**: React 版を本体にする。
  → React を使わない利用者が最初から対象外になります。
- **止めるべき条件**: ラッパが薄くならず、結局フレームワークごとの実装が要ると判明したとき。

## D-007 ライセンスはコードが MIT、データが ODbL（2026-09-14）

- **決めたこと**: `LICENSE` は MIT 1 枚。データ側の条件は `LICENSES.md` に分けて書く。
- **根拠**: **スタイル JSON はデータではなく表現**なので ODbL の対象外です。
  一方でベースタイルは OSM 由来で ODbL。**混ぜて書くと、どちらも守られません。**
- **採らなかった案**: 全体を ODbL にする。
  → UI 部品まで ODbL になり、**採用の敷居が理由なく上がります**。
- **必ず守ること**: 画面から `© OpenStreetMap contributors` を消さない。

## D-008 費用削減を目的に掲げない（2026-09-14）

- **決めたこと**: 「地図の費用が下がる」を、この製品の目的にも成果にも書かない。
- **根拠**: 座標の取得元が「その提供者の地図の上に表示すること」を条件にしている場合、
  **ベース地図だけを差し替える自由はありません。**
  効く条件が限られるものを効果として約束すると、**採用した人が後で困ります。**
- **採らなかった案**: 訴求として使う。→ 一番伝わりやすい言葉ですが、正確ではありません。
