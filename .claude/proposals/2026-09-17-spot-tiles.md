### 圧縮は効きません

zip でも同じです。**「圧縮して配る」は選択肢になりません。**

## 決めたこと（提案）

### 1. 「地域」ではなく「現場」の単位で切れるようにする

```bash
pnpm tiles:extract -- --center=135.4959,34.7024 --radius=2km --zoom=12-15 -o office.pmtiles
#=> 2.9 MB
```

**半径で指定します。**「会社の位置から最寄駅まで入れたいから 2km」という考え方が、
使う人の頭の中と一致するためです。bbox の 4 隅を計算させません。

### 2. 切り出した箱の外へ出られないようにする

```html
<mmj-map tiles="/maps/office.pmtiles" style-url="/maps/modern-dark.json"
         center="135.4959,34.7024" zoom="16" fit-to-tiles>
  <mmj-marker lnglat="135.4959,34.7024" popup="弊社はこちら"></mmj-marker>
</mmj-map>
```

`fit-to-tiles` を付けると、**PMTiles のヘッダにある bounds と min/max zoom を読んで、
MapLibre の `maxBounds` / `minZoom` / `maxZoom` を自動で設定**します。

- **切り出した人が、同じ数字を 2 回書かなくて済みます**（ずれる余地を作らない）
- ヘッダに入っていることは確認済みです（`pmtiles show` が bounds / min zoom / max zoom を出す）

### 3. それでも出る「無いところ」を、黒い穴にしない

`maxBounds` があっても、**境界ぎりぎりでは一瞬だけ外が見えます**。
いまはそこが地の色（`#1B1F24`）で、**黒い穴**に見えます。

今日、全国タイルで同じ壊れ方をしました（太平洋に黒い矩形）。
**タイル件数も `verify` も正常で、テストも全部通っていました。撮って初めて分かりました。**

**どう見せるかは `DESIGN.md` の領域なので、私は決めません。**
決めるべきことだけ挙げます。

- 地の色のままにするか、**それと分かる見せ方**にするか
- 「この地図はこの範囲だけです」と伝えるか、黙って端で止めるか

### 4. 配り方は 3 段にする。**全部落とす人も想定内**

| 段 | 誰が | 容量 | 置き場 |
|---|---|---|---|
| **現場** | 会社 HP・店舗 1 つ | 1〜13 MB | **自社サーバー。**ダウンロードして置くだけ |
| **地方** | 複数拠点・エリア検索 | 数百 MB | GitHub Releases（1 資産 2 GB まで） |
| **全国** | 全国規模の媒体 | 2.60 GiB | **自分で切り出す**（下） |

**まるごと欲しい企業は出ます。それでいいはずです。**

- 自社で持つなら、**転送量はあちらの話**になります
- **全国は、こちらが配らなくても手に入ります。**上流を pin してあるので
  （D-010）、`pnpm tiles:extract -- japan` を回せば**同じものが再現できます**
  （実測 14m27s / 90 リクエスト）。**これが D-001「データを持たない」の効き目です**
- 2.60 GiB は GitHub Releases の 1 資産 2 GB を越えるので、**そもそも置けません。**
  置けないことが問題にならない構造になっています

### 5. デモは GitHub Pages に同梱する

**GitHub Pages は Range を返します**（実測: `206 Partial Content` / `Accept-Ranges: bytes`）。
だめだったのは Range ではなく**サイズ**（1 ファイル 100 MB / サイト 1 GB）でした。

デモ用に切ったら乗りました。

| 中身 | 容量 |
|---|---|
| 全国 z0-9（俯瞰） | 35 MB |
| 大阪中心部 z10-15（街路まで） | 31 MB |
| **merge 後** | **62.8 MB** |

**R2 も鍵も要りません。**全国を俯瞰でき、大阪は街区まで寄れます。
**公開デモが「配信元がありません」のままである理由が消えます。**

## 採らなかった案とその理由

- **圧縮して配る。** → **効きません**（実測で 0 バイト）。
- **Range 配信を主にして、CORS と Referer で守る。**
  → CORS は**ブラウザにしか効きません**。サーバー経由は止まりません。
  Referer は偽装できます。**守れるのは転送量だけ**で、それなら配らないほうが確実です。
  （ただし Range 配信を残す場合の既定は今日閉じました・`ALLOW_ORIGINS`）
- **署名 URL / トークン。** → 「HTML を 1 枚書くだけで地図が出る」という
  原案 §4.1 の目標と真正面からぶつかります。**導入の敷居を上げた時点で負けです。**
- **全国を分割して Releases に置く。** → 置けますが、**利用者に merge させる**ことになります。
  自分で切り出せるなら、そちらのほうが手数が少ないはずです。

## これを止めるべき条件

- **「半径で切る」が実際の使い方と合わないとき。**
  拠点が 10 か所ある会社は、半径ではなく「拠点リスト」で切りたいはずです。
  そのときは中心を複数受ける形（MultiPolygon・D-013 で仕組みは入っています）。
- **`fit-to-tiles` が窮屈だと言われたとき。**
  「外も見せたいが、タイルが無いだけ」という使い方があるなら、境界で止めるのは邪魔です。
