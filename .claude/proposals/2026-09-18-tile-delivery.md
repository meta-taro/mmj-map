# 提案 — タイルの配り方を決める。CF が要るのか要らないのか（2026-09-18）

**これは提案です。決定ではありません。**

問われたこと:

> 分割結合するタイルベクター、pnpm で問題ない設計。そのうえで CF いるのかいらないのか。

先に結論を書きます。

- **利用者に分割も結合も見せない。**`pnpm dlx` の 1 コマンドで 1 ファイルが出る形にする
- **そのために PMTiles の書き出しを自前で持つ。**外部の実行ファイルを入れさせない
- **CF は、いまの要件では要らない。**要るのは 1 つの条件が立ったときだけ（末尾）

関連: [現場の単位で切り出す](2026-09-17-spot-tiles.md) / [リリース計画](2026-09-16-release-plan.md)

---

## 分かったこと（実測）

### 地方ブロックは、そのままでは結合できない

関西（z0-8）と関東（z0-8）を別々に切り出して `pmtiles merge` にかけた結果:

```
Failed to merge: 7 overlapping tiles, starting with 0 0 0. Inputs must be disjoint
```

**`z0/0/0` は 1 枚で地球全体**なので、どの地方ブロックにも必ず入ります。
`pmtiles merge` は重複を許しません。**「ぽちぽち落として結合」は成立しません。**

回避は「低い倍率を別ファイルにする」形です（全国タイルで実際に使っている・D-013）。
ただしそれは**利用者に 2 ファイル落とさせて merge を打たせる**ことになります。

**それは要件（混乱させない）に反します。**だから、この分割は**こちら側の内部事情に留めます。**

### npm パッケージにタイルは入れられない

- **入れるべきではない。**`pnpm install` のたびに数百 MB〜数 GB を引くことになります
- npm はバイナリ配信の場所ではありません
- D-001（データを持たない）にも反します

**npm で配るのはコードだけ**です。スタイル JSON・部品・CLI。

### 書き出しライブラリを探した（ECC `development-workflow.md` §0）

npm で `pmtiles` を検索した 15 件のうち、**書けると書いてあるのは 1 つだけ**でした。

| | `s2-pmtiles@1.1.2` |
|---|---|
| 説明 | PMTiles V3.0 と S2PMTiles V1.0 を読み書き |
| ライセンス | MIT |
| 依存 | **ゼロ** |
| 最終公開 | 2025-12-22（**約 9 か月前**） |
| 週間 DL | **45 回** |

**試作した結果、素直な経路では標準 v3 になりませんでした。**

```
生成物  50 4d 00 00 00 00 00 03   "PM\0\0\0\0\0\x03"   ← S2 独自形式
本物    50 4d 54 69 6c 65 73 03   "PMTiles\x03"        ← 標準 v3

$ pmtiles verify out.pmtiles
  magic number not detected. confirm this is a PMTiles archive
```

`S2PMTilesWriter(writer, type, compression)` に v3 を指定する引数はありません。
**v3 を書く経路が存在するかは、まだ分かっていません**（配布物が圧縮されていて追えなかった）。

**週 45 DL・最終更新 9 か月前のパッケージに、中核の経路を預けるのは弱い**と判断します（ECC §12）。

## 決めたこと（提案）

### 利用者から見える形は、1 コマンド 1 ファイル

```bash
pnpm dlx @modern-map-japan/tiles get \
  --center=135.4959,34.7024 --radius=2km -o public/maps/office.pmtiles
```

```html
<mmj-map tiles="/maps/office.pmtiles" style-url="/maps/modern-dark.json" fit-to-tiles>
  <mmj-marker lnglat="135.4959,34.7024" popup="弊社はこちら"></mmj-marker>
</mmj-map>
```

**利用者が知るのは中心と半径だけ。**低倍率ファイルも地方ブロックも merge も出てきません。

### PMTiles の書き出しを自前で持つ

**外部の実行ファイル（go-pmtiles）を利用者に入れさせない。**そこが混乱の源です。

- 上流からの Range 読み出しは**すでにあります**（`packages/http-range`）
- MVT のデコーダも**自前で書いてあります**（D-012）。同じ判断です
- PMTiles v3 は仕様が公開されていて、書くのはヘッダ＋ディレクトリ＋タイル本体です

**`tools/tiles` の go-pmtiles 呼び出しは残します。**開発側（全国 2.60 GiB の切り出し）は
そのままで構いません。**利用者向けの経路だけを自前にします。**

### 配るのはコードだけ。タイルは配らない

| 配るもの | どこで | 大きさ |
|---|---|---|
| スタイル JSON・部品・CLI | **npm** | 数十 KB |
| デモ用タイル | **GitHub Pages に同梱** | 62.8 MB |
| 利用者のタイル | **利用者が CLI で作る** | 1〜13 MB |

## CF は要るのか

**いまの要件では要りません。**

上の形なら、こちらがタイルを配る場面がありません。利用者の CLI が上流（Protomaps）から
直接取って、その場で 1 ファイルを作ります。デモは GitHub Pages で足ります
（**Pages が Range を返すことは実測済み**）。

### CF が要るのは、この条件が立ったときだけ

**「上流に負荷を寄せたくない」と判断したとき。**

利用者の CLI は、Protomaps が公開している **138 GB の日次ビルド**へ Range で取りに行きます。

- **少人数なら問題ありません。**それがあのビルドの用途です
- **数が増えたら、他人のサーバーに負担を寄せることになります**
- 上流のビルドは **61 版・約 2 か月で消えます**。古い pin は取れなくなります（D-014 で検出はできる）

そこを避けるなら、**こちらがミラーを持つ**ことになります。その場合でも:

| ミラーする対象 | 置き場 | CF が要るか |
|---|---|---|
| 地方ブロック（数百 MB） | **GitHub Releases**（1 資産 2 GB まで） | **不要** |
| 全国 1 ファイル（2.60 GiB） | Releases に載らない | **要る**（または分割） |

**つまり CF が本当に必要なのは「全国 2.60 GiB を 1 ファイルで、こちらから配る」場合だけ**です。

### 分かっていないこと

**GitHub Releases の転送量の上限を、私は知りません。**
GitHub は Releases の帯域を「soft limit」としか言っておらず、数字を公開していません。
**ミラーを置く判断をする前に、ここは調べる必要があります。**

## 採らなかった案とその理由

- **地方ブロックを配って、利用者に merge させる。**
  → **実測で merge が失敗します**（低倍率タイルが重複）。
  分けて配れば結合できますが、**2 ファイル落として 1 コマンド打たせる**ことになります。
  要件（混乱させない）に反します。
- **go-pmtiles を利用者に入れさせる。**
  → 単体の実行ファイル 1 つとはいえ、**`pnpm add` の世界から出る**ことになります。
  「HTML を 1 枚書くだけ」という原案 §4.1 の目標から遠ざかります。
- **`s2-pmtiles` に中核を預ける。**
  → 試作が標準 v3 にならず、週 45 DL・9 か月更新なし。**ECC §12 に照らして弱い。**
  ただし**v3 を書く経路が見つかれば、自前実装より速い**ので、完全には捨てません。
- **タイルを npm パッケージに同梱する。**
  → `pnpm install` のたびに数百 MB を引きます。D-001 にも反します。

## これを止めるべき条件

- **PMTiles の書き出しを自前で持つのが、思ったより重いと分かったとき。**
  そのときは `s2-pmtiles` の v3 経路を探すか、go-pmtiles 前提へ戻します。
  **戻すこと自体は難しくありません**（`tools/tiles` が既にその形です）。
- **上流への負荷が現実の問題になったとき。**ミラーの話になります。
- **2 媒体が「全国 1 ファイルをこちらから配ってほしい」と言ったとき。**
  そこで初めて CF が必要になります。
