# 提案 — ラベルをモードで持つ（日本語のみ / インバウンド）（2026-09-16）

**これは提案です。決定ではありません。**
`DESIGN.md` にも `.claude/decisions.md` にも手を入れていません。

出発点は「インバウンド向けにルビを振れないか」という問いでした。
**調べた結果、要件はルビ（組版）ではなく「同じラベルの中に、看板と照合できて
声に出せる読みが並ぶこと」だと分かりました。** そこから設計を起こします。

関連: [bbox の提案](2026-09-16-umeda-namba.md) / [デザイン提案](2026-09-16-design-umeda-namba.md)

---

## 決めたこと（提案）

1. **ラベルをモードで持つ。** `ja`（日本語のみ・既定）と `inbound`（日本語＋ローマ字）。
2. **スタイル JSON は 1 枚のまま。** MapLibre の `state` ＋ `global-state` 式で切り替える。
3. **ローマ字を振る対象を種別で切る。** 駅と地名には振り、施設には振らない。
4. **inbound は「文字が増えるモード」ではなく「駅と地名に寄せて、その他を減らすモード」**にする。
5. **「英語のみ」モードは作らない。**

## 実測値

推測で設計していません。以下はすべてこの機械で測った値です。

### タイルの中身（`kansai.pmtiles` の `14/14358/6506`＝梅田を、MVT までデコード）

| レイヤ | 名前つき | `name:en` あり | うち**英単語混じり**（＝読みでない） |
|---|---|---|---|
| places | 83 | **83（100%）** | 0 |
| pois | 300 | 124（41%） | **61** |
| roads | 275 | 111（40%） | — |
| water | 3 | 3（100%） | 0 |

**`name:ja_kana` / `name:ja_rm` はタイルのスキーマに存在しません（0 件）。**
かなの振り仮名は、このタイルからは出せません。

### OSM 側（Overpass・梅田〜難波の bbox を 1 回だけ取得）

| 対象 | 件数 | かな | `name:ja_rm` | `name:en` |
|---|---|---|---|---|
| 駅 | 40 | 18% | **98%** | **100%** |
| 地名・町丁 | 207 | **95%** | 9% | **98%** |
| 施設・店 | 5,341 | 3% | 5% | 29% |

**かなとローマ字で、埋まり方が逆転しています。**
かなは地名に厚く駅に薄い。ローマ字は駅に厚く地名に薄い。
**両方を同じ規則で扱えません。**

### `name:ja_rm` より `name:en` を使う

OSM の `name:ja_rm` は厳密なヘボン式で、`Ōsaka` / `Ōsaka-Umeda` / `Nanba` になります。
一方、**実際の駅名標は `Osaka` / `Namba`** です。
**要件が「看板との照合」である以上、`name:en` のほうが正しい**という逆転が起きます。

### カタカナ語にローマ字を振ると逆効果になる

```
スターバックス → Sutābakkusu   （看板は Starbucks）
モスバーガー   → Mosu Bahga    （看板は MOS Burger）
タイムズ       → Taimuzu       （看板は Times）
```

**読みとしては正しいが、通じないし看板とも一致しません。**
「読みだから正しい」とは限らない実例です。施設に振らない理由がこれです。

## 実装方式 — スタイル 1 枚に `state` を持つ

```json
{
  "version": 8,
  "state": { "labelMode": { "default": "ja" } }
}
```

```json
"text-field": ["case",
  ["all", ["==", ["global-state", "labelMode"], "inbound"],
          ["has", "name:en"]],
  ["format", ["get", "name"], {},
             "\n", {},
             ["get", "name:en"], { "font-scale": 0.72 }],
  ["get", "name"]
]
```

切り替えは `map.setGlobalStateProperty("labelMode", "inbound")` の 1 行。

**`["has","name:en"]` は必須です。** pois は 41% しか持たないため、これが無いと
**空行だけが残って行間が空きます**。

### 実機で確認済み（Chrome ＋ maplibre-gl 6.9.0）

```json
{ "api": "function", "styleLoaded": true, "errors": [],
  "switched": true, "errorsAfter": [] }
```

- `Map.prototype.setGlobalStateProperty` が存在する
- `state` ＋ `global-state` 式を含むスタイルが**エラー 0 で読み込まれる**
- モード切替後も**エラー 0**

> 公開されている `@maplibre/maplibre-gl-style-spec` には `global-state` が
> 入っていませんでした。**文書ではなく実機で確かめています。**

### 採らなかった案

- **スタイルを `ja` / `inbound` の 2 枚に割る。**
  → **配色の正本が 2 つになります。** 色を直すたびに 2 か所直すことになり、
  必ずずれます。D-002「スタイルは生成物ではなく作品」が壊れる壊れ方です。
- **JS から `setLayoutProperty` で各レイヤの `text-field` を差し替える。**
  → 動きますが、**ラベルの規則がスタイル JSON の外（JS）へ漏れます。**
  スタイルが正本でなくなります。
- **「英語のみ」モードを足す。**
  → それは既に世にあるもので、かつ**「どれが何と読まれているか分からない」という
  今回の出発点そのもの**です。作ると、解こうとした問題を自分で作り直すことになります。

## ラベルの規則（種別で切る）

| 種別 | `ja` | `inbound` |
|---|---|---|
| **駅**（pois / kind=station） | `name` | **2 行**（`name:en` 100%・駅名標と一致） |
| **地名・町丁**（places） | `name` | **2 行**（`name:en` 98%・読みになっている） |
| 施設・店（pois その他） | `name` | **1 行のまま** |
| 道路（roads） | `name` | 幹線だけ 2 行にするか**未決**（`name:en` 40%） |
| 水域（water） | `name` | 1 行のまま |

## inbound は「文字が増えるモード」ではない

2 行にするとラベルの箱が縦に伸び、**衝突が増えて出る地物が減ります。**
梅田周辺は 1 行の現状でも詰まっているため、これは確実に起きます。

したがって inbound では、同じ `global-state` 式で次も切り替えます。

- `text-size` を一段下げる
- `symbol-sort-key` で**駅を最優先**にする（インバウンドが探すのは駅）
- 施設ラベルの `minzoom` を上げて間引く

**「駅と地名に寄せて、その他を減らす」がモードの本体で、ローマ字はその結果です。**
文字を足すだけの実装にすると、梅田が黒く潰れます。

## 本物のルビが要る場合

字ごとの対応（この漢字がこう読む）は **MapLibre では原理的に出せません。**
テキストが 1 つの箱としてレイアウトされ、セクション単位のベースライン移動が無いためです。

**それは地図のラベルではなく Popup の仕事**だと考えます。
タップした地物について、かな・ローマ字・読み上げまで出す。
**S2（Marker / Popup / Cluster を Web Components で）の範囲**です。
地図のラベルは 2 行までと割り切ると、衝突も増えません。

## 人が決めること

1. **既定モード** — `ja` を既定にする提案（国内利用が既定、インバウンドは明示的に選ぶ）
2. **切り替えの口** — 地図上のトグル / URL パラメータ / npm パッケージの option、どれを正とするか
3. 道路（幹線）を 2 行の対象に含めるか

## これを止めるべき条件

- **`global-state` が上流で不安定なら、`setLayoutProperty` 方式へ落とす。**
  実機では動いていますが、公開の style-spec には入っていませんでした。
  **仕様として固まっていない可能性があります。** 落ちたら気づけるよう、
  スタイルの読み込みエラーを握り潰さないこと。
- **`name:en` の中身が地域によって崩れるなら、対象の切り分けを見直す。**
  この実測は**梅田〜難波だけ**のものです。他の都市で同じ比率とは限りません。

# 追記 — 実物で測った（2026-09-16）

上の提案の**一番弱い所は「2 行にすると衝突で地物が減る」の程度を測っていないこと**でした。
そこを実測しました。**リポジトリのファイルは書き換えていません。**
ブラウザに渡すスタイルだけを差し替えて描画し、`queryRenderedFeatures` で
**実際に配置されたラベルの数**を数えています。

画角: 梅田〜難波（center `135.4995, 34.6845` / zoom 13.4 / 1400×1000）。

## 測った結果

| | `ja` | `inbound`（町丁名にも振る） | **`inbound`（町丁名は 1 行）** |
|---|---|---|---|
| 駅ラベル | 29 | 27 | **27** |
| 町丁名ラベル | 282 | 233（**−17%**） | **303（+7%）** |
| 水域ラベル | 8 | 8 | 8 |

**結論: 町丁名にローマ字を振らず、字を一段小さくすれば、ローマ字を足しても情報量は落ちません。**
むしろ町丁名は増えます（字が小さくなって衝突が減るため）。

**駅は 29 → 27 で、主要駅はすべて残りました。**
大阪 / 大阪梅田 / 梅田 / 北新地 / 淀屋橋 / 本町 / 心斎橋 / なんば / 難波 / 日本橋 /
鶴橋 / 京橋 / 天満橋 / 北浜 / 森ノ宮 / 弁天町 / 大正 — いずれも両モードで出ています。

### 町丁名に振らない理由

**インバウンドは丁目で歩きません。**価値が低いわりに画面を最も食います。
ここを 1 行に留めることが、**駅のローマ字を出す原資**になります。

## 分かった 2 つの事実

### 1. いまのスタイルには駅ラベルのレイヤが 1 つも無い

`styles/modern-dark.json` の symbol レイヤは
`label-place-city` / `label-place-neighbourhood` / `label-water` の 3 つだけです。
**駅名が 1 つも出ていなかったのは、データではなくスタイルの問題**でした。
この実験では `label-station`（`pois` / `kind=station`）を足しています。

**タイル側は主要駅の序列を持っています。**`pois` の `min_zoom` が、
大阪・大阪梅田 = 11、中之島・梅田・北新地・淀屋橋 = 13、
西梅田・東梅田・肥後橋・渡辺橋・福島 = 14。
`symbol-sort-key` にこれを渡すだけで、**衝突時に主要駅が勝ちます**（序列を自作しなくてよい）。

```json
"filter": ["all", ["==", ["get","kind"], "station"],
                  ["<=", ["get","min_zoom"], ["zoom"]]],
"symbol-sort-key": ["get", "min_zoom"]
```

### 2. ズーム依存の式は `case` の中に入れられない

モードで `text-size` のカーブごと切り替えようとして落ちました。

```
layers[18].layout.text-size:
  Only one zoom-based "step" or "interpolate" subexpression may be used in an expression.
```

**`interpolate` を外側に出し、stop の値の側でモードを切る**必要があります。

```json
"text-size": ["interpolate", ["linear"], ["zoom"],
  13, ["case", ["==", ["global-state","labelMode"], "inbound"], 9, 10],
  16, ["case", ["==", ["global-state","labelMode"], "inbound"], 11.5, 13]]
```

## 残っている弱い所

- **測ったのは 1 画角・1 ズーム（13.4）だけです。**z15 以上の徒歩スケールでは
  比率が変わる可能性があります。
- ラベル数は 1 回のキャプチャの値で、配置が落ち着く途中の可能性があります。
  駅の一覧に `梅田` が入る回と入らない回がありました（画面には出ています）。
  **厳密な比較が要るなら、複数回の平均を取るべきです。**
- 道路（幹線）のローマ字は**まだ試していません**。
