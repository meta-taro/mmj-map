## 0.5.0（2026-10-10）

### ピンの色を、点ごとに変えられます（`pin-color-key` / `pin-colors`）

いままでピンは全部同じ色でした。業種や分類で塗り分けたいときは、
`icons` と同じ「**値 → 何か**」の対応で渡します。

```html
<mmj-poi pin-color-key="category"
         pin-colors="cafe:#C9A227,ramen:#E4572E,books:#4E8098"></mmj-poi>
```

- **写真のピンにも、分類の絵のピンにも効きます**
- **対応に無い値は、いままでの色**です（知らない値で点が消えません）
- **色は導入側が指定します**。MMJ は色を作りません
- **16 進だけ**を受けます——`red` のような名前は捨てます
  （canvas は読めない色を黙って透明にするので、通すと**ピンが消えた理由が分からない**）

**色だけに意味を持たせないでください**。色で業種を表すなら、`icon-key` の絵や
一覧の文字でも分かるようにしてください。

### 媒体のプランで並べ替えられます（`rank-key` / `rank-order`）

```html
<mmj-poi rank-key="plan" rank-order="platinum,gold,silver,bronze"></mmj-poi>
```

**MMJ は「ゴールド」の意味を知りません**。段の数も名前も媒体ごとに違うので、
受け取るのは「どの属性を見るか」と「どの順に並べるか」だけです。

- **一覧も `‹ ›` の送りも `?shop=` の復元も、同じ順になります**
- **同じ順位の中では元の順を保ちます**（読み込むたびに入れ替わりません）
- **並びに無い値と、値を持たない点は末尾**。綴り違いや新しいプランで、
  **店が一覧から消えることはありません**
- HTML に書いた一覧は**作り直しません**。並べ替えるだけなので、検索に出ていた文字は消えません

> **お金を払った順に並ぶ一覧は、広告です**。日本では 2023-10 から
> ステルスマーケティング規制があり、**広告だと分かる表示**が必要です。
> MMJ は表示文言を決めません（媒体の判断です）。**掲載順がプランで決まっているなら、
> そう分かる表示を出してください。**

### この頁の書き方を変えました（挙動は同じ）

**最初の節を「どういうときに向くか」にしました**。いままでは制約の節が先頭で、
AI にこのパッケージを要約させると**制約だけが主役**になっていました。制約は消していません。
`keywords` にも、探している人が使う言い方（自前配信・鍵不要・オフライン）を足しています。

## 0.4.0（2026-10-09）

### 写真があることが、押す前に分かります

写真を持つ点は、**ピンの中がその写真**になります。小さくて何が写っているかまでは
分かりませんが、**「ここに写真がある」は伝わります**。開くまで分からないなら、
写真は無いのと同じでした。

- **道のり案内**（`<mmj-route>`）は `image` を持つ点が自動でそうなります
- **お店の点**（`<mmj-poi>`）は `pin-image` にその属性名を渡します

```html
<mmj-poi src="./shops.geojson" card-images="photos" pin-image="photos"></mmj-poi>
```

`card-images` と同じ属性をそのまま渡せます（複数枚なら先頭の 1 枚）。
写真を持たない点はいままでどおりです。**分類の絵（`icons`）も同じピンの形**に揃いました。

**件数が多くても大丈夫です**。地図が実際に描こうとしたぶんだけ作るので、
1,000 件規模でも作るのは画面に出ている数十枚です（同時に持つのは 96 枚まで）。

> **別オリジンの写真には CORS が要ります**。ピンは写真を丸く切ってから地図へ渡すため、
> `Access-Control-Allow-Origin` が無いと読めません。**そのときは何も出さず、
> いままでの丸（または分類の絵）のまま**です。同じオリジンの写真なら設定は不要です。

### 写真に撮影者の表記を添えられます（`card-image-credit`）

写真の提供元が「**写真に添えて撮影者名を表示すること**」を条件にしていることがあります。
説明文に混ぜると区別が付かず、タブに入れると開かないと見えません。

```html
<mmj-poi card-images="photos"
         card-image-credit="photo_author"
         card-image-credit-href="photo_author_url"></mmj-poi>
```

**写真のすぐ下に小さく 1 行**出ます。**リンクが無ければ名前だけ出て、行は消えません**
（出すこと自体が条件なので、リンクの有無で消えてはいけません）。
写真が 1 枚も出ていない地物では出ません。

**写真ごとに撮影者が違う場合は、この口では足りません**（その地物に 1 つです）。

### セキュリティ修正：`javascript:` の抜け道を塞ぎました

**0.3.0 以前を使っている場合は、更新をおすすめします。**

URL の途中にタブや改行を挟むと（`java<TAB>script:`）、こちらの判定をすり抜けていました。
ブラウザは URL を読む前にタブと改行をどこからでも取り除くので、`href` に入った瞬間
`javascript:` に戻ります。**押すとスクリプトが走る**状態でした。

撮影者のリンクだけでなく、**`card-href`・SNS リンク（`card-links`）・`icons`** も
同じ判定を通っていました。判定をブラウザと同じ読み方（`URL`）に替えています。

## 0.3.0（2026-10-07）

### 時間で動くラスタ（`<mmj-raster frames=…>`）

```html
<mmj-raster src="./rain/{t}/{z}/{x}/{y}.png"
            frames="09:00,10:00,11:00" interval="650" autoplay></mmj-raster>
```

`src` の `{t}` が時刻の番号に置き換わります。見出しは置く側が書きます——
「10 分後」なのか「10/7 10 時」なのかは、置く側しか知りません。

時刻ぶんをまとめて置き、見せ方だけを切り替えます。毎回 source を作り直すと、
切り替えのたびに取りに行って白く抜けます。

| 足したもの | |
| --- | --- |
| `frames` | 時刻の見出しを読点区切りで |
| `interval` | 送りの間隔（ミリ秒）。既定 700 |
| `autoplay` | 置いただけで動き出す |
| `showFrame(n)` / `play()` / `pause()` | 頁側からの操作 |
| `mmj-raster-frame` | 送られたときに飛ぶ（`detail.index` / `detail.label`） |
| `mmj-raster-ready` | 用意ができたときに飛ぶ（`detail.frames`） |

実物: <https://meta-taro.github.io/mmj-map/rain.html>

### 台風（`<mmj-typhoon>`）

```html
<mmj-typhoon src="./data/typhoon.json"></mmj-typhoon>
```

強風域（黄）・暴風域（赤）・予報円（白の破線）・進路線（実績は実線／予報は破線）・中心。
報道で見る形に合わせてあります。

色は作っていません。黄と赤は気象庁の配色を写したものです。
**予報円は塗りません**——あれは中心の位置の不確かさで、暴風域とは別物です。
塗ると「この範囲が暴風」と読まれます。

**予報はしません**。渡された点を描くだけで、外挿も補間もしません。

### 挙動が変わるところ

**`<mmj-raster>` の `min-zoom` / `max-zoom` を、layer ではなく source に書くようにしました。**

タイルの有無は source の話です。layer に書くと「その範囲の外では描かない」に
なるだけで、

- 持っていない倍率のタイルを**取りに行き続けます**（z8 だけ置いた頁で 404 が 188 件）
- `min-zoom` を下回る倍率で開くと、**1 滴も描かれません**（タイルはあるのに真っ新）

既に `min-zoom` / `max-zoom` を「表示する倍率の範囲」として使っていた場合、
意味が変わります。**持っている倍率**を書いてください。

### 上げる前に読むところ

**MapLibre 6 に対応しました。5 系のままでも動きます。**
`peerDependencies` は `maplibre-gl: ">=5"` のままで、部品が見ているのは
`window.maplibregl` だけです。ここは変えていません。

ただし **MapLibre 6 は ESM だけを配っており、`dist/maplibre-gl.js`（UMD）がありません**。
6 系を使うなら、読み込み方がこう変わります。

```html
<!-- 5 系 -->
<script src="https://cdn.jsdelivr.net/npm/maplibre-gl@5.24.0/dist/maplibre-gl.js"></script>

<!-- 6 系 -->
<script type="module">
  import * as maplibregl from "https://cdn.jsdelivr.net/npm/maplibre-gl@6.12.0/dist/maplibre-gl.mjs";
  window.maplibregl = maplibregl;
</script>
```

版の数字だけ 6 に書き換えると **404 になり、地図が 1 枚も出ません**。
`import maplibregl from`（既定の輸入）も `undefined` になります（6 系に既定の輸出が無いため）。
`import * as` で受けてください。

6 系は **WebGL2 必須**です。自分で配信する場合、`.mjs` が JavaScript の
content-type で返ることも確かめてください（`application/octet-stream` で返すと、
HTTP 200 のままブラウザが実行を拒み、**地図だけが出ません**）。

### 店舗カード（`mmj-poi`）

点を押すと開くカードが、1 枚の吹き出しから**中身のある画面**になりました。

- 写真（複数あるときは横に流れる帯）・星・長文・ラベル付きリンク
- タブ（品書き・クーポン・営業時間など、任意の数）
- 開いたまま隣の店へ送る。開いている店は `?shop=` に残る（共有できる）
- 営業時間を曜日ごとに。口コミ本文
- `card-live` — 時間で変わる中身は、**開いたときに取りに行く**
- `card-rich` — 項目を名指ししたときだけ、本文を HTML として読む（既定は文字のまま）
- 地図と並ぶ一覧。探せる・検索エンジンに出る・キーボードで届く

### 地図まわり

- **点を自前の SVG アイコンにできる**
- **現在地**（`locate`）。通信が無くても出る
- **地図の時点を地図の中に出す**。配っているタイルがいつのものか
- **建物を、走っている地図でも立てたり寝かせたりできる**
- 地図の部品（帰属表示・縮尺・操作ボタン）も、読み込んだ配色に合わせる
- スマホでは下から出る面、PC では横から出る面。つまんで動かせる。全画面ボタン

### 直したもの

- **グリフをスタイルの位置から解く**。公開先が `/<repo>/` の下にあると
  `../glyphs/` が 1 つ上を指し、**本番だけで 404** になっていた。
  地図は出てラテン文字だけが閲覧側のフォントに化けるので、画面では気づけない
- 地図を押してカードを閉じたとき、点が元に戻らなかった
- 面が地図に沈み、吹き出しが真っ黒になっていた
- 矢印で送ったとき「いまここ」が分からなかった
